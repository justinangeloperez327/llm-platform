# Group 3 — Authentication and sessions

## Architecture

FastAPI is the session authority. Next.js is a same-origin UI gateway through /api/auth/* rewrites. The backend stores users and revocable session records in PostgreSQL. Tokens are generated by a cryptographically secure RNG and only SHA-256 token hashes are stored in the database. Cookies are HttpOnly, SameSite=Lax, host-only, with a bounded expiration. Passwords use Argon2id (argon2-cffi).

The Next.js proxy checks the **presence** of a cookie to improve navigation. This is not an authorization check: the frontend checks /auth/me, and all private backend resources must independently validate the session.

## Auth endpoints

- POST /api/v1/auth/register: create user, return public profile, set a session cookie
- POST /api/v1/auth/login: verify credentials, create a new session
- GET /api/v1/auth/me: validate session and return public profile
- POST /api/v1/auth/logout: revoke current session and expire its cookie

All mutating auth endpoints require an allowed Origin; the backend must be configured for the public browser origin(s). Frontend forms use the same-origin /api/auth/* rewrite; backend remains at http://127.0.0.1:8000 in development.

## Windows setup

From the repository root: `docker compose up -d --wait db`.

From `services/api`:
```powershell
python -m pip install -e ".[dev]"
python -m alembic upgrade head
python -m uvicorn app.main:app --reload --port 8000
```

In a separate terminal:
```powershell
cd apps/web
npm ci
npm run dev
```
Visit /register to create your first account, then /chat.

## Security and limitations

- Configure SESSION_COOKIE_SECURE=true and HTTPS for deployment; production without secure cookies fails initialization.
- CORS is allowlisted. Same-origin CSRF defense is based on Origin validation and SameSite cookies.
- Five failed logins per peer-IP/email pair in a rolling 15-minute window return 429. This per-identifier DB limiter is not a complete distributed edge-level defense; production needs rate limiting before the app.
- Cookie content never includes the password or user ID.
- No email verification, password reset, MFA, organization roles or tenant data policies yet.
- Group 4 owns additional entities, tenant authorization and resource policies. Group 5 owns model/chat integration.
- Browser-local prompt drafts are not encrypted; do not store secrets in them. A logged-out browser retains old local drafts; authenticated data storage is future work.
- No OAuth or external providers enabled.
- Database migrations are explicit; backend never silently creates tables at startup.
